# Cross-Reference Map

This page answers one question for a builder or a reuser: which template each session uses, which kit page it fills, what that work feeds, and which destination-pack files the session reads. A family running one trip can skip it.

The map is a derived view. Each session page is the home of its own template and artifact, and each pack's routing contract is the home of its routing. Where this page and a session page disagree, the session page wins. Where this page and a routing contract disagree, the contract wins. Either way, fix this page to match its source.

## Part 1: The artifact flow

Each phase has one table. Its four columns follow a session's work from the blank to the finished binder, the way the [trip starter kit][kit]'s one-artifact, one-home rule describes it.

- **Template it uses** names the blank in `framework/templates/` that the session's artifact is written on. "The session page" means the session's own Workspace is the blank. "None" means the session uses a fresh page or scratch paper.
- **Kit page it fills** names the page in the trip starter kit where the filled copy lives. "None" means the kit has no page for it, and the filled page goes into the binder as it is.
- **Output it feeds** names where the work is carried forward: the checkpoint or later session that takes it up, then the finished page in the kit's [outputs folder][outputs] it ends on. A binder tab is added wherever the [print index][print] files the page. "The tab it fits best" is the rule [Session 50][s50] gives for a working page the print index does not list. The cell follows the work's route forward. Each later session's Materials line is the full list of what that session reads.

These are named once, here, so the rows stay short:

- Nearly every session with a research step adds entries to the [Source Log][t-source]. Its row is Session 04's, where the log starts.
- Many sessions read the [Trip-Basics Card][t-basics] and the [Current Family Travel Assumptions][t-assume] page. Their row is Session 00's, where they are filled in.
- At each checkpoint, a grown-up fills in a [Parent Review Form][t-review], which goes behind tab 10, and the child writes a [Decision Record][t-decision] for the [decision log][k-decision]. The checkpoint rows name the Decision Record and the decision log.
- The [Question Parking Lot][t-parking] belongs to no single session. The child starts [the kit's copy][k-parking] the first time a question pulls them off track, and the [Adult Follow-Up Questions][o-follow] page collects from it.
- Three blanks support a row without being its artifact. The [Simple Citation Forms][t-citation] page gives the form for writing down each kind of source, and Sessions 06, 08, 25, 28 and 31 link it. The [Planning Assumption][t-assumption] field is a block of rows on every research card, and Session 16 links it. The [Baseline Reflection][t-baseline] blank is a printable form of Session 01's reflection, which the session writes on a fresh page.
- Two builder templates, the [Student Session Template][t-student] and the [Parent Guide Page Template][t-parent], are for writing new pages. Two optional kit cards go on the trip itself: the [Final Countdown Card][k-countdown] and the [In-Trip Capture Card][k-capture], which Session 54 reads.

## Part 2: The destination routing mirror

The routing contract in each destination pack, at `destinations/<pack>/session_inserts/README.md`, is canonical for which session reads which pack file. This part copies its session rows and its parent-facing rows, in the contract's order. Every pack filename here is in inline code and unlinked, so no framework page links into a pack. A session this mirror does not list reads no pack file. The contract also holds the slot schema and the rule for how each row's session writes its pointer, and the [add-a-destination guide][add] says how to build a pack to it.
